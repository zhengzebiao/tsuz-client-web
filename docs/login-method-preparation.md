# 登录形态准备清单与开通项说明

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档名称 | 登录形态准备清单与开通项说明 |
| 适用范围 | 使用 `tsu-cli` 工具模板生成的 MFE 微前端项目 |
| 当前登录形态 | 邮箱登录、账号登录、微信登录 |
| 文档版本 | v0.2 |

## 2. 说明目的

本文档说明当前阶段三种登录形态需要准备的资料、需要开通的能力、研发接入前需要确认的事项和上线前核对清单。

当前阶段暂只支持：

1. 邮箱登录。
2. 账号登录。
3. 微信登录。

以下登录方式暂不纳入 MVP 范围：

- 手机号验证码登录。
- Google 登录。
- Apple 登录。
- GitHub 登录。
- 企业 SSO。
- 其他第三方登录。

---

## 3. 当前登录形态总览

| 登录形态 | 是否需要第三方平台 | 是否需要开通/审核 | 主要准备事项 | 推荐优先级 |
| --- | --- | --- | --- | --- |
| 邮箱登录 | 需要邮件服务商 | 需要域名/DNS 配置 | 发信域名、邮件模板、验证码策略 | P1 |
| 账号登录 | 不一定 | 不需要外部平台审核 | 账号体系、密码策略、找回流程 | P1 |
| 微信登录 | 需要微信开放平台 | 需要主体认证和应用审核 | 微信开放平台账号、AppID、AppSecret、回调域名 | P1 |

- 法务或合规联系人。

### 4.2 协议与合规资料

- 用户协议链接。
- 隐私政策链接。
- 个人信息收集清单。
- 第三方 SDK 清单。
- 用户注销说明。
- 用户数据删除或更正入口。
- 客服联系方式。

### 4.3 系统基础能力

- 统一用户 ID 规则。
- 登录态管理方案。
- token/session 刷新方案。
- 登录失败次数限制。
- 账号锁定策略。
- 登录日志和审计日志。
- 登录相关埋点。
- 主应用登录入口。
- 子应用登录态消费能力。

### 4.4 域名与环境

至少需要准备以下环境：

| 环境 | 示例 | 用途 |
| --- | --- | --- |
| 本地环境 | `http://localhost:3000` | 本地开发调试 |
| 测试环境 | `https://test.example.com` | 测试和验收 |
| 生产环境 | `https://app.example.com` | 正式用户访问 |

需要提前确认：

- 主应用访问域名。
- 登录回调地址。
- Cookie 作用域。
- HTTPS 证书。
- 前后端跨域策略。

## 5. 邮箱登录

### 5.1 方案说明

邮箱登录是指用户通过邮箱完成身份识别。可以有两种实现方式：

1. 邮箱验证码登录：用户输入邮箱，接收验证码后登录。
2. 邮箱 + 密码登录：用户使用邮箱作为账号，输入密码登录。

当前建议优先支持：

```txt
邮箱验证码登录 + 邮箱可作为账号登录标识
```

这样既能降低用户忘记密码的成本，也能为账号找回、风险提醒、通知触达提供基础能力。

### 5.2 需要准备的资料

| 资料 | 说明 |
| --- | --- |
| 发信域名 | 例如 `mail.example.com` 或 `example.com` |
| 发信邮箱 | 例如 `noreply@example.com` |
| 发信名称 | 用户在邮箱里看到的发件人名称 |
| 邮件 Logo | 邮件头部品牌标识 |
| 邮件模板 | 登录验证码、注册确认、找回密码、风险提醒等 |
| 隐私政策链接 | 邮件底部或登录页展示 |
| 用户协议链接 | 登录页展示 |
| 客服邮箱 | 用户遇到登录问题时联系 |

### 5.3 需要开通的服务

选择一个邮件服务商：

- 阿里云邮件推送。
- 腾讯云邮件推送。
- Amazon SES。
- SendGrid。
- Mailgun。
- 其他企业邮箱或邮件服务。

需要开通或配置：

- 发信域名验证。
- SPF。
- DKIM。
- DMARC。
- 发信地址。
- 邮件模板。
- 发送额度。
- 退信/投诉监控。

### 5.4 DNS 配置准备

邮箱登录通常需要运维或域名管理员配合配置 DNS。

常见 DNS 记录包括：

```txt
TXT 记录：SPF
TXT/CNAME 记录：DKIM
TXT 记录：DMARC
MX 记录：如服务商要求
CNAME 记录：发信域名验证
```

### 5.5 邮件模板建议

#### 登录验证码邮件

需要包含：

- 产品名称。
- 验证码。
- 验证码有效期。
- 如果不是本人操作，请忽略或联系安全支持。
- 隐私政策和用户协议链接。

示例文案：

```txt
您正在登录 {产品名称}，验证码为：{code}
验证码 {expireMinutes} 分钟内有效。
如果不是您本人操作，请忽略本邮件。
```

### 5.6 风控和频控建议

需要限制：

- 同一邮箱每分钟发送次数。
- 同一邮箱每日发送次数。
- 同一 IP 每分钟发送次数。
- 同一设备每日发送次数。
- 验证码错误次数。

建议策略：

| 场景 | 建议限制 |
| --- | --- |
| 同一邮箱发送验证码 | 60 秒内最多 1 次 |
| 同一邮箱每日验证码 | 10-20 次 |
| 同一 IP 每分钟请求 | 5-10 次 |
| 验证码错误次数 | 连续 5 次后临时限制 |

### 5.7 需要研发实现的能力

- 邮箱格式校验。
- 发送验证码接口。
- 验证码校验接口。
- 验证码过期机制。
- 验证码错误次数限制。
- 邮箱用户自动注册或绑定策略。
- 登录成功后生成统一用户 ID。
- 登录成功事件埋点。
- 登录失败事件埋点。

### 5.8 风险与注意事项

- 邮件可能进入垃圾箱。
- 新域名发信信誉需要积累。
- 不要在邮件里放敏感信息。
- 验证码有效期不宜过长。
- 邮箱登录对国内普通 C 端用户可能不如微信登录顺滑。

## 6. 账号登录

### 6.1 方案说明

账号登录是指用户通过账号 + 密码完成登录。账号可以是：

- 用户名。
- 邮箱。
- 系统分配账号。
- 管理员创建账号。

当前建议：

```txt
普通用户可用邮箱作为账号；管理后台或测试账号可使用用户名 + 密码。
```

### 6.2 需要准备的资料

| 资料 | 说明 |
| --- | --- |
| 账号规则 | 用户名、邮箱、系统账号的格式规则 |
| 密码规则 | 长度、复杂度、特殊字符要求 |
| 找回密码流程 | 通过邮箱找回或管理员重置 |
| 初始账号创建方式 | 用户注册、后台创建、导入账号 |
| 账号状态定义 | 正常、冻结、禁用、注销 |
| 管理员说明 | 谁可以创建、重置、禁用账号 |

### 6.3 不需要外部开通，但需要自建能力

账号登录通常不需要第三方平台审核，但需要后端自建以下能力：

- 用户表。
- 账号表。
- 密码哈希存储。
- 登录接口。
- 密码修改接口。
- 密码重置接口。
- 账号锁定机制。
- 登录失败记录。
- 登录审计日志。
- 管理员账号管理能力。

### 6.4 密码策略建议

| 项目 | 建议 |
| --- | --- |
| 最小长度 | 8 位以上 |
| 复杂度 | 至少包含字母和数字，管理账号可要求特殊字符 |
| 明文存储 | 严禁 |
| 哈希算法 | bcrypt、argon2、scrypt 等 |
| 密码重试 | 连续失败后限流或锁定 |
| 找回密码 | 通过邮箱验证码或安全链接 |

### 6.5 账号状态建议

| 状态 | 说明 |
| --- | --- |
| active | 正常可登录 |
| locked | 因失败次数过多临时锁定 |
| disabled | 管理员禁用 |
| deleted | 用户注销或删除 |
| pending | 待激活 |

### 6.6 需要研发实现的能力

- 账号唯一性校验。
- 密码强度校验。
- 密码哈希存储。
- 登录失败次数统计。
- 账号锁定和解锁。
- 找回密码。
- 修改密码。
- 管理员重置密码。
- 登录成功/失败埋点。
- 异常登录审计。

### 6.7 风险与注意事项

- 用户容易忘记密码，需要完善找回机制。
- 账号密码登录容易受到撞库和暴力破解攻击。
- 密码不能明文存储，也不能可逆加密存储。
- 管理员账号应启用更严格的安全策略。
- 对外开放注册时，需要防止批量注册。

## 7. 微信登录

### 7.1 方案说明

微信登录是指用户通过微信扫码或微信授权完成登录。对于国内 C 端用户，微信登录通常转化较好。

在 MFE 项目中，微信登录仍然由主应用统一触发：

```txt
子应用需要登录 → 主应用打开微信登录 → 微信授权/扫码 → 主应用处理回调 → 主应用同步登录态给子应用
```

子应用不直接接入微信登录。

### 7.2 需要准备的资料

| 资料 | 说明 |
| --- | --- |
| 企业营业执照 | 微信开放平台主体认证使用 |
| 企业联系人 | 用于平台认证和通知 |
| 产品名称 | 微信授权页展示 |
| 产品 Logo | 微信开放平台应用资料 |
| 官网地址 | 应用审核使用 |
| 隐私政策链接 | 应用审核和登录页展示 |
| 用户协议链接 | 应用审核和登录页展示 |
| 回调域名 | 微信 OAuth 回调使用 |
| 应用说明 | 产品用途、登录场景说明 |

### 7.3 需要开通的服务

需要准备并开通：

- 微信开放平台账号。
- 主体认证。
- 网站应用或移动应用。
- AppID。
- AppSecret。
- OAuth 授权能力。
- 授权回调域名。
- 必要时配置 UnionID 能力。

如果后续还接入公众号或小程序，需要额外确认：

- 微信公众号平台。
- 微信小程序平台。
- 开放平台绑定关系。
- UnionID 打通策略。

### 7.4 回调域名准备

微信登录需要配置授权回调域名，例如：

```txt
app.example.com
```

注意：

- 通常配置的是域名，不是完整 URL。
- 测试环境和生产环境要分别规划。
- 本地开发一般不能直接使用 localhost 作为正式回调域名。
- 回调地址需要由主应用统一处理。

建议主应用回调路径：

```txt
https://app.example.com/auth/wechat/callback
```

### 7.5 微信登录模式

#### Web 扫码登录

适合 PC Web：

```txt
用户点击微信登录 → 展示二维码 → 用户手机扫码确认 → 微信回调主应用 → 主应用完成登录
```

#### 微信内网页授权

适合微信内打开页面：

```txt
用户在微信内访问 → 触发网页授权 → 获取 code → 后端换取 openid/unionid → 完成登录
```

### 7.6 用户标识说明

微信常见用户标识：

| 标识 | 说明 |
| --- | --- |
| openid | 用户在某个应用下的唯一标识 |
| unionid | 用户在同一开放平台主体下多个应用之间的统一标识 |

建议：

- 如果只有一个微信应用，openid 可用于绑定。
- 如果未来可能接公众号、小程序、移动应用，建议规划 unionid。

### 7.7 需要研发实现的能力

- 微信登录入口。
- 获取微信授权地址。
- 微信扫码二维码展示。
- 微信回调处理。
- code 换取 openid/unionid。
- 微信用户与系统用户绑定。
- 首次微信登录自动创建用户。
- 已有账号绑定微信。
- 解绑微信能力，如需要。
- 登录成功/失败埋点。

### 7.8 风险与注意事项

- 微信开放平台认证和应用审核需要时间。
- AppSecret 必须保存在服务端，不能暴露给前端。
- 回调域名必须提前规划。
- 微信昵称、头像等用户信息获取能力受平台政策影响。
- 如果不规划 unionid，后续多微信生态应用打通会有成本。

## 8. 三种登录方式之间的账号绑定关系

### 8.1 推荐用户主键

系统内部必须有自己的 `userId`，不能直接使用邮箱、用户名、openid 作为主键。

推荐关系：

```txt
userId
  ├── email identity
  ├── username/password identity
  └── wechat identity
```

### 8.2 账号绑定表建议

| 字段 | 说明 |
| --- | --- |
| identityId | 身份记录 ID |
| userId | 系统用户 ID |
| identityType | email / username / wechat |
| identifier | 邮箱、用户名、openid/unionid |
| verified | 是否已验证 |
| createdAt | 绑定时间 |
| lastLoginAt | 最近登录时间 |

### 8.3 绑定策略建议

- 同一个邮箱只能绑定一个用户。
- 同一个微信 openid/unionid 只能绑定一个用户。
- 一个用户可以同时绑定邮箱、账号、微信。
- 用户首次用微信登录时，如果没有绑定记录，可以自动创建新用户。
- 用户首次用邮箱登录时，如果没有账号，可以自动创建新用户。
- 管理账号可以由后台创建，不一定允许公开注册。

## 9. 登录埋点要求

三种登录方式都需要统一上报登录事件。

### 9.1 核心事件

| 事件名 | 触发时机 | 关键字段 |
| --- | --- | --- |
| `login_start` | 用户开始登录 | loginMethod、sourceAppId、routePath |
| `login_success` | 登录成功 | loginMethod、userId、isNewUser |
| `login_fail` | 登录失败 | loginMethod、reason、errorCode |
| `logout` | 退出登录 | sourceAppId、userId |
| `account_bind_success` | 绑定登录身份成功 | identityType、userId |
| `account_bind_fail` | 绑定登录身份失败 | identityType、reason |

### 9.2 loginMethod 建议枚举

```txt
email_code
username_password
wechat_qrcode
wechat_oauth
```

## 10. 上线前核对清单

### 10.1 邮箱登录

- 发信服务商已开通。
- 发信域名已验证。
- SPF/DKIM/DMARC 已配置。
- 登录验证码模板已配置。
- 邮件发送额度已确认。
- 邮件验证码频控已实现。
- 邮件送达率监控已准备。

### 10.2 账号登录

- 用户表和账号表已设计。
- 密码哈希策略已确定。
- 登录失败限流已实现。
- 账号锁定策略已实现。
- 找回密码流程已实现或规划。
- 管理员账号安全策略已确认。

### 10.3 微信登录

- 微信开放平台账号已注册。
- 主体认证已完成。
- 网站应用或移动应用已创建。
- AppID 和 AppSecret 已获取。
- 授权回调域名已配置。
- 主应用微信回调页面已实现。
- openid/unionid 绑定策略已确认。

### 10.4 通用

- 用户协议和隐私政策已准备。
- 登录入口都在主应用。
- 子应用不直接处理登录。
- 登录成功后可回跳原页面。
- 登录失败有明确提示。
- 登录相关事件已上报。
- 登录日志和审计日志已保存。

## 11. 推荐落地顺序

建议按以下顺序实施：

1. **账号登录**：最容易自建，适合作为后台、测试和兜底登录方式。
2. **邮箱登录**：补充用户自助注册、登录和找回能力。
3. **微信登录**：面向国内 C 端用户，提高登录转化。

如果主应用需要尽快可用，建议先上线：

```txt
账号登录 + 邮箱登录
```

微信登录并行准备开放平台认证和应用审核。

---

## 12. 结论

当前阶段登录方式收敛为邮箱登录、账号登录、微信登录是合理的：

- 邮箱登录适合账号找回、通知触达和低成本验证。
- 账号登录适合后台、管理端、测试账号和兜底场景。
- 微信登录适合国内 C 端用户，有利于降低登录门槛。

三种方式都必须统一接入主应用登录体系，子应用只消费登录态，不独立实现登录。
