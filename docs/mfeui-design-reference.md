## 2. 设计目标

### 2.1 目标

本文件用于提供一套适合 MFE 微前端架构的 UI 设计参考，重点覆盖：

- 主应用整体视觉框架。
- 所有子应用的页面设计方向。
- 主应用登录页 / 登录弹窗设计方向。
- 其他页面的统一参考规范。
- 设计系统的基础边界和一致性要求。

### 2.2 设计原则

1. **统一但不僵化**：所有子应用共享同一设计语言，但允许业务模块有自己的内容布局。
2. **主应用优先**：登录、导航、全局通知、权限拦截、错误兜底由主应用统一承接。
3. **子应用轻量化**：子应用关注业务内容和局部操作，不重复建设全局壳能力。
4. **信息层级清晰**：让用户一眼区分主导航、子应用内容、操作区和状态提示。
5. **适配广告位**：页面设计需为广告位、活动位、通知位预留稳定布局。
6. **响应式优先**：默认支持桌面端，兼容常见移动端浏览器。

## 3. 视觉基调建议

### 3.1 风格方向

推荐采用：

- 简洁。
- 现代。
- 中性偏稳重。
- 适度科技感。
- 偏平台型产品风格。

### 3.2 颜色建议

| 角色 | 建议 |
| --- | --- |
| 主色 | 蓝色系或品牌色 |
| 辅助色 | 青色、紫色、绿色，用于状态和图表 |
| 中性色 | 灰阶为主，用于背景、边框、辅助文案 |
| 成功色 | 绿色 |
| 警告色 | 橙色 |
| 错误色 | 红色 |
| 信息色 | 蓝色 |

建议整体遵循：

- 背景尽量浅。
- 内容区域留白充足。
- 强调色只用于关键按钮和关键状态。

### 3.3 字体与间距

建议采用统一的设计 token：

- 标题：24 / 20 / 16 / 14 px 分层。
- 正文：14 px 为主。
- 辅助说明：12 px。
- 基础间距：8px 网格体系。
- 卡片圆角：8px 或 12px。
- 页面边距：16px / 24px / 32px 递进。

## 4. 结构总览

### 4.1 全局结构

```txt
┌───────────────────────────────────────────┐
│ Top Bar / Global Header                   │
├──────────────┬────────────────────────────┤
│ Side Nav     │ Main Content Area          │
│              │                            │
│              │ Page Header / Breadcrumb   │
│              │ Content Panels / Cards     │
│              │ Ads / Tips / States        │
│              │                            │
└──────────────┴────────────────────────────┘
```

### 4.1.1 导航结构建议

主应用建议采用**左侧菜单承载子应用入口**的结构，适合平台型 MFE 场景。

推荐层级如下：

```txt
主应用左侧一级菜单 = 子应用入口
子应用内部左侧菜单 = 该子应用自己的功能菜单（可选）
登录页 / 落地页 = 不展示左侧菜单
```

#### 推荐原因

- 子应用数量多时，左侧菜单最适合快速切换。
- 用户能清楚感知当前在哪个子应用。
- 主应用统一承接登录、权限和全局状态。
- 子应用内部还能再拆出二级菜单，保持业务独立性。

#### 结构示例

```txt
┌────────────────────────────────────────────────────┐
│ Logo | Search | User                               │
├──────────────┬─────────────────────────────────────┤
│ 用户中心      │                                     │
│ 数据看板      │                                     │
│ 报表中心      │          子应用内容区               │
│ 会员中心      │                                     │
│ 管理后台      │                                     │
│ 广告管理      │                                     │
└──────────────┴─────────────────────────────────────┘
```

#### 左侧菜单建议

- 一级菜单按“子应用”组织，而不是按页面无限下钻。
- 一级菜单名称要短、稳定、可识别。
- 当前子应用高亮，其他子应用折叠或置于同级列表。
- 子应用内部功能过多时，再在内容区内提供二级菜单、Tabs 或侧边二级栏。
- 不建议全站所有页面都用深层左侧菜单，否则会显得笨重。

### 4.2 页面层级

| 层级 | 说明 |
| --- | --- |
| 主应用层 | 登录、全局导航、布局、权限拦截、通知、统一错误页 |
| 子应用层 | 每个业务应用独立内容区与局部操作区 |
| 页面层 | 页面标题、筛选、列表、详情、表单、图表等 |
| 组件层 | 卡片、表格、弹窗、抽屉、标签、提示条、按钮等 |

## 5. 主应用 UI 设计参考

### 5.1 主应用壳

主应用建议采用：

- 左侧主导航 + 顶部工具栏 + 内容区。
- 或顶部导航 + 内容区（若菜单较少）。

建议展示：

- 品牌 Logo。
- 当前登录用户信息。
- 消息中心。
- 全局搜索。
- 登录/退出按钮。
- 权限相关入口。

### 5.2 主应用首页

主应用首页建议包含：

- 欢迎区。
- 常用子应用入口卡片。
- 最近访问记录。
- 待处理事项。
- 系统公告。
- 数据摘要卡片。

### 5.3 主应用全局状态

需要统一设计以下状态：

- 未登录态。
- 登录中。
- 登录成功态。
- 会话过期态。
- 无权限态。
- 网络异常态。
- 系统异常态。

## 6. 所有子应用设计参考

下面按当前文档中出现的子应用或业务页面类型，给出设计方向。

### 6.1 用户中心

#### 设计定位

用户中心是用户个人信息、账号管理、登录信息、偏好设置的集合页。

#### 页面内容建议

- 头像、昵称、账号信息。
- 邮箱绑定。
- 微信绑定。
- 安全设置。
- 登录设备或登录记录。
- 偏好设置。
- 账号注销入口。

#### 设计风格

- 偏个人资料管理风格。
- 信息卡片化。
- 表单区清晰，强调修改和保存操作。

#### 页面结构参考

```txt
[头像 + 昵称 + 账号概览]
[账号安全卡片]
[绑定方式卡片]
[偏好设置卡片]
[危险操作区]
```

---

- 批量操作。

#### 设计风格

- 高效率。
- 结果区域稳定。
- 筛选项可折叠。

### 6.13 强权限页面 / 403 页面

#### 设计定位

当用户已登录但无权限访问时展示。

#### 页面内容建议

- 权限不足提示。
- 返回首页按钮。
- 联系管理员按钮。
- 申请权限入口。

#### 设计风格

- 语气友好。
- 明确原因。
- 不暴露敏感权限信息。

#### 页面内容建议

- 返回首页按钮。
- 重试按钮。
- 联系支持入口。

## 7. 登录页面设计参考

### 7.1 登录页总体要求

登录页只存在于主应用，子应用不独立做登录页。

登录页建议支持：

- 邮箱登录。
- 账号登录。
- 微信登录。

### 7.2 页面布局

推荐布局：

```txt
┌──────────────────────────────────────────────┐
│ Logo / Brand                                 │
│                                              │
│ [Tab: 邮箱登录 | 账号登录 | 微信登录]         │
│                                              │
│ [输入区 / 二维码区 / 提示区]                  │
│                                              │
│ [登录按钮]                                   │
│ [协议勾选 / 隐私政策]                        │
│ [忘记密码 / 其他入口]                        │
└──────────────────────────────────────────────┘
```

### 7.3 邮箱登录 UI

#### 参考结构

- 邮箱输入框。
- 验证码输入框。
- 获取验证码按钮。
- 登录按钮。
- 邮件未收到帮助文案。

#### 状态设计

- 默认态。
- 输入错误态。
- 验证码发送中。
- 验证码倒计时。
- 登录失败态。
- 加载中态。

### 7.4 账号登录 UI

#### 参考结构

- 账号输入框。
- 密码输入框。
- 显示/隐藏密码按钮。
- 登录按钮。
- 忘记密码入口。

#### 状态设计

- 默认态。
- 账号不存在。
- 密码错误。
- 账号锁定。
- 登录中。

### 7.5 微信登录 UI

#### 参考结构

- 微信扫码区域。
- 刷新二维码按钮。
- 二维码过期提示。
- 手机确认登录提示。
- 扫码失败兜底。

#### 状态设计

- 等待扫码。
- 已扫码待确认。
- 扫码成功。
- 二维码过期。
- 网络失败。

## 8. 子应用接入设计规范

### 8.1 统一页面壳

所有子应用建议使用统一页面壳：

- 顶部导航保持一致。
- 主体内容按子应用区分。
- 列表、详情、表单、图表遵循统一组件规范。

### 8.2 页面识别规则

每个子应用至少需要：

- 应用名称。
- 应用 Logo 或图标。
- 应用主题色。
- 页面标题规范。
- 空状态和错误状态规范。
- 权限不足时的统一提示。

### 8.3 广告位预留规则

如果页面可能承载广告，设计时要预留：

- 顶部横幅位。
- 内容区插入位。
- 右侧栏位。
- 底部位。

## 11. 推荐下一步

如果要继续推进设计落地，建议先补三套高优先级稿：

1. **主应用登录页**：邮箱 / 账号 / 微信三种登录方式。
2. **主应用首页壳**：导航、子应用入口、用户区、状态区。
3. **子应用通用模板页**：列表页、详情页、表单页。

## 12. 结论

这份设计参考的目标不是替代正式 UI 设计稿，而是先把 MFE 项目的视觉范围和页面边界定下来。

重点是：

- 登录只在主应用。
- 所有子应用共享统一设计语言。
- 其余页面按业务类型提供参考方向，而不是强行统一成一个模板。
- 设计应优先考虑后续扩展、权限、广告和数据看板。
