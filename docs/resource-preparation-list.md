## 4. 必须申请或配置的资源

### 4.1 域名与 HTTPS

| 资源 | 用途 | 建议示例 | 备注 |
| --- | --- | --- | --- |
| 主域名 | 主应用访问入口 | `app.example.com` | 必须 |
| API 域名 | 后端统一接口入口 | `api.example.com` | 必须 |
| 登录回调域名 | 微信授权回调、登录回跳 | `app.example.com/auth/callback` | 必须 |
| BI 域名 | BI 看板或数据查询入口 | `bi.example.com` | 建议 |
| 测试域名 | 测试和验收环境 | `test.example.com` | 建议 |
| HTTPS 证书 | 全站安全访问 | 通配或单域证书 | 必须 |

#### 需要做的事

- 购买或确认域名归属。
- 配置 DNS 解析。
- 申请 HTTPS 证书。
- 配置回调域名白名单。

#### 需要部署的能力

- 用户信息接口。
- 权限接口。
- 配置接口。
- 埋点接收接口。
- 广告回传接口。

### 4.4 数据库资源

| 资源 | 用途 | 备注 |
| --- | --- | --- |
| 用户库 | 用户、账号、身份绑定 | 必须 |
| 权限库 | 角色、权限、资源范围 | 必须 |
| 配置库 | 路由配置、广告配置、开关配置 | 必须 |

- PostgreSQL：业务数据、权限数据、配置数据、基础事件数据。
- 如果后续事件量很大，可再考虑拆分分析型存储，但当前主库优先用 PostgreSQL。
- 当前方案不再默认使用 MySQL。

## 6. 最小起步配置

### 6.1 第一阶段 A 最小起步配置

第一阶段 A 只做工程骨架与接口契约，最小资源准备为：

1. GitHub 仓库与 GitHub Actions 权限。
2. GHCR 或等价 Docker 镜像仓库权限。
3. 本地 / test Docker 运行环境。
4. `docker-compose.test.yml` 内 PostgreSQL 容器。
5. `docker-compose.test.yml` 内 Redis 容器。
6. test 环境变量模板，不提交真实 secret。
7. 如需要预留 test 部署，占位准备 test 服务器、SSH key、部署用户，但本阶段不要求真实部署可用。

第一阶段 A 暂不要求：

- product 服务器。
- product PostgreSQL / Redis 接入。
- 邮件服务商真实开通。
- 微信开放平台真实开通。
- BI 看板资源。
- 腾讯 / 百度广告资源。

### 6.2 完整 MVP 最小起步配置

如果想先快速启动完整 MVP，建议至少先准备以下资源：

1. 主域名、API 域名、HTTPS 证书。
2. 前端静态托管。
3. API 服务器。
4. Auth Service。
5. BFF/Gateway。
6. 数据库。
7. Redis。
8. 日志与监控。
9. 对象存储。
10. 邮件服务商账号。
11. 微信开放平台账号。
12. 埋点接收服务和 BI 存储。
